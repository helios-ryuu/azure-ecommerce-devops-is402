PHẦN 2. PHÂN LOẠI CÁC THÀNH PHẦN THEO MÔ HÌNH DỊCH VỤ ĐÁM MÂY
========================================================================================================================

* LÀM RÕ VỊ TRÍ TRIỂN KHAI INGRESS NGINX TRONG AKS (CHUẨN CLOUD-NATIVE / CKAD):
  - Phân vùng mạng: Toàn bộ Frame 1 (INGRESS & EDGE) và Frame 2 (AKS WORKLOADS) đều nằm trọn vẹn trong cụm AKS thuộc Azure Private VNet.
  - Azure Public Load Balancer (Layer 4): Dịch vụ mạng PaaS do Azure tự động cấp phát khi tạo Service type: LoadBalancer, tiếp nhận traffic HTTPS (Port 443) từ Internet vào Public IP.
  - Ingress NGINX Controller: Hoạt động dưới dạng các Pods chạy trên chính Worker Nodes của cụm AKS, được cô lập trong namespace chuyên trách "ingress-nginx". Pods này đảm nhiệm SSL/TLS Termination và Path/Host-based Routing.
   - Workloads nghiệp vụ: Toàn bộ các Pods của Frontend (PHP 8.5 & Apache 2.4.62, CDN UI), User Service (Java 25 & Spring Boot 4.1.1) và Order Service (Python 3.14 & FastAPI 0.141.1+) chạy trong namespace nghiệp vụ riêng biệt "ecommerce-prod", tuyệt đối không mở IP public ra ngoài Internet mà chỉ giao tiếp an toàn qua K8s ClusterIP nội bộ.

1. IaaS (Infrastructure as a Service - Hạ tầng dưới dạng dịch vụ):
   - AKS Worker Nodes Pool: Các máy ảo Azure Virtual Machines (hệ điều hành Ubuntu Linux chuyên dụng cho container runtime)
     cung cấp tài nguyên tính toán vật lý/ảo hóa gồm vCPU, RAM, và Local SSD để vận hành các Docker container.
   - Azure Virtual Network (VNet) & Subnets: Mạng ảo riêng biệt cô lập hệ thống, phân chia các subnet chuyên trách:
     + Subnet cụm ứng dụng (snet-aks: 10.0.1.0/24)
     + Subnet dịch vụ lưu trữ (snet-db: 10.0.2.0/24)
   - Network Security Group (NSG): Tường lửa ảo kiểm soát các luồng traffic inbound/outbound giữa các subnet,
     ngăn chặn truy cập trái phép từ Internet vào database và private microservices.

2. PaaS (Platform as a Service - Nền tảng dưới dạng dịch vụ):
   - Azure Kubernetes Service (AKS Control Plane): Microsoft tự động quản trị toàn bộ Kubernetes API server, etcd,
     scheduler và controller manager (SLA 99.95%), đảm bảo zero-maintenance đối với master nodes.
   - Azure Database for PostgreSQL Flexible Server v18 (PostgreSQL 18.6): Hệ quản trị cơ sở dữ liệu quan hệ được Azure quản lý toàn diện
     (tự động sao lưu, vá lỗi tự động, tính sẵn sàng cao High Availability với tự động failover).
   - Azure Cosmos DB (Core SQL API): Cơ sở dữ liệu NoSQL phân tán toàn cầu, đa mô hình với cam kết SLA độ trễ < 10ms
     cho thao tác đọc/ghi dữ liệu, hỗ trợ tự động mở rộng theo nhu cầu (Autoscale Request Units - RU/s).
   - Azure Cache for Redis: Bộ nhớ đệm phân tán in-memory siêu tốc (độ trễ dưới 1 mili-giây), giảm thiểu nghẽn I/O
     cho cơ sở dữ liệu chính và lưu trữ PHP Session state.
   - Azure Container Registry (ACR): Kho lưu trữ Docker container image riêng tư, tích hợp cơ chế quét lỗ hổng
     bảo mật tự động (Microsoft Defender for Cloud).
   - Azure Synapse Analytics (Serverless SQL Pool): Công cụ xử lý và truy vấn dữ liệu lớn phân tán theo mô hình Serverless,
     thực thi truy vấn SQL trực tiếp trên hồ dữ liệu Data Lake thông qua lệnh OPENROWSET mà không cần cấp phát cụm máy chủ cố định.

3. FaaS (Function as a Service - Chức năng dưới dạng dịch vụ):
   - Azure Functions (Python Runtime - Consumption Plan): Kiến trúc phi máy chủ (Serverless compute), tự động thực thi logic
     nghiệp vụ dựa trên sự kiện (Event-driven). Tự động kích hoạt thông qua Cosmos DB Change Feed để sinh file hóa đơn
     điện tử (PDF) và gửi email thông báo xác nhận đơn hàng cho khách hàng mà không tiêu tốn tài nguyên khi rảnh rỗi.

4. SaaS (Software as a Service - Phần mềm dưới dạng dịch vụ):
   - Power BI Service: Nền tảng trực quan hóa dữ liệu kinh doanh phân tán, cung cấp giao diện Dashboard với 4 báo cáo chuyên sâu,
     khả năng tương tác linh hoạt (Slicers, Drill-down, Bookmark Navigation), bảo mật dữ liệu cấp dòng (Row-Level Security)
     và hỗ trợ Power BI Mobile App.
   - GitHub Actions: Hệ thống tự động hóa CI/CD pipeline toàn diện trên đám mây, tự động build mã nguồn, kiểm thử, quét mã
     bảo mật và deploy tự động sang AKS.

PHẦN 3. CHI TIẾT CÁC LUỒNG DỮ LIỆU & LOGIC NGHIỆP VỤ (DATA FLOWS & SEQUENCES)
========================================================================================================================

1. Luồng duyệt Web & Lưu Session/Cache (Web Browsing & Caching Flow):
   - Bước 1: Khách hàng truy cập thông qua Web Browser hoặc Mobile Device qua giao thức bảo mật HTTPS (Port 443).
   - Bước 2: Lưu lượng đi qua Azure Public Load Balancer (Layer 4) vào các Ingress NGINX Pods (namespace: ingress-nginx) trên AKS.
     Ingress Controller giải mã SSL/TLS termination, căn cứ vào Host/Path để định tuyến lưu lượng Web (`/`, `/product/*`, `/cart`)
     tới `Frontend Web Service (PHP)` (namespace: ecommerce-prod).
   - Bước 3: `Frontend Web Service (PHP)` render 4 view chính của ứng dụng:
     + View 1: Trang chủ (Home Page) - Hiển thị banner và danh mục sản phẩm nổi bật.
     + View 2: Trang chi tiết (Product Detail Page) - Hiển thị thông số chi tiết, giá tiền và số lượng tồn kho.
     + View 3: Trang thêm vào giỏ hàng (Cart Add) - Cho phép khách hàng chọn số lượng và thêm vào giỏ hàng.
     + View 4: Trang liệt kê giỏ hàng (Cart List / Checkout) - Hiển thị bảng tổng hợp mặt hàng, số lượng và tổng hóa đơn.
   - Bước 4: Để tối ưu tốc độ đọc và lưu trữ phiên, Frontend đọc/ghi dữ liệu phiên (PHP Session) và truy vấn bộ nhớ đệm
     danh mục sản phẩm trực tiếp từ `Azure Cache for Redis` với độ trễ sub-millisecond (< 1ms).

2. Luồng Đăng ký & Xác thực người dùng (Auth & User Registration Flow):
   - Bước 1: Khách hàng thực hiện đăng ký tài khoản mới hoặc đăng nhập tại giao diện web/app.
   - Bước 2: Request gửi tới endpoint `/api/v1/auth/register` hoặc `/api/v1/auth/login`. Qua Azure Public LB, Ingress NGINX Pods
     định tuyến trực tiếp yêu cầu này tới `User Service (Java Spring Boot)` (namespace: ecommerce-prod).
   - Bước 3: `User Service` xử lý nghiệp vụ xác thực (hashing mật khẩu bằng BCrypt, kiểm tra tính hợp lệ dữ liệu), sau đó
     mở giao dịch ACID lưu trữ vào `Azure Database for PostgreSQL (User / ACID)`.
   - Bước 4: Khi đăng nhập thành công, `User Service` ký số và phát hành JWT Token (JSON Web Token) trả về cho client.

3. Luồng Giỏ hàng, Đặt hàng & Giao tiếp 2 Service (Cart, Order & Inter-Service Flow):
   - Lưu ý luồng xử lý: Request `(REST /cart)` từ Frontend Web Service (PHP) đi trực tiếp tới
     `K8s Service: order-svc` trong cụm nội bộ, không qua User Service.
   - Bước 1: Khi khách hàng thao tác giỏ hàng hoặc bấm thanh toán ("Đặt hàng"), Frontend gửi REST API request kèm JWT Token
     tới `K8s Service: order-svc`.
   - Bước 2 (Giao tiếp giữa 2 Microservices): `order-svc` gọi ngược lên `User Service (Java Spring Boot)` thông qua endpoint
     nội bộ `/api/v1/auth/validate` để xác thực JWT Token và lấy thông tin trạng thái người dùng (Verify JWT / User Status).
   - Bước 3 (Triển khai Blue/Green Deployment): `K8s Service: order-svc` điều phối lưu lượng qua cơ chế hoán đổi Selector:
     + Mặc định 100% lưu lượng sản xuất điều phối tới `Order Service Blue [v1]` (phiên bản ổn định).
     + Khi phát hành phiên bản mới, thực hiện hoán đổi nhãn Selector sang `Order Service Green [v2]` tức thời với 0% Downtime.
   - Bước 4: Order Pods thực thi ghi nhận đơn hàng mới và cập nhật tồn kho vào cơ sở dữ liệu `Azure Cosmos DB (Catalog & Orders)`
     với cam kết SLA độ trễ đọc/ghi < 10ms.

4. Luồng xử lý Bất đồng bộ Serverless FaaS (Event-Driven Invoice & Email Notification Flow):
   - Bước 1: Khi đơn hàng mới được ghi nhận thành công vào Cosmos DB, tính năng `Azure Cosmos DB Change Feed` tự động phát
     hiện bản ghi thay đổi theo thời gian thực (real-time stream).
   - Bước 2: Change Feed kích hoạt (Trigger) hàm không máy chủ `Azure Functions (Python Trigger)`.
   - Bước 3: Hàm Azure Functions thực thi hoàn toàn bất đồng bộ (Non-blocking async):
     + Tự động lưu trữ hóa đơn điện tử vào container invoices trên Azure Blob Storage.
     + Ghi nhận nhật ký thông báo email mô phỏng (Mock Notification Logging) trên hệ thống giám sát.
     => Luồng chính mua hàng của người dùng không bị nghẽn (Zero latency overhead).

5. Luồng Tự động ETL/ELT sang Data Lakehouse & Trực quan hóa Power BI (Automated Lakehouse ETL & BI Flow):
   - Lưu ý luồng trích xuất dữ liệu: Cả `Azure DB for PostgreSQL` và `Azure Cosmos DB` đều có đường xuất dữ liệu độc lập chạy thẳng xuống
     `Azure Data Lake Storage Gen2`.
   - Bước 1 (Trích xuất tự động):
     + Dữ liệu quan hệ từ `Azure DB for PostgreSQL` (User profiles, Transaction logs) được trích xuất định kỳ (Scheduled Export)
       thành định dạng Parquet.
     + Dữ liệu tài liệu lớn từ `Azure Cosmos DB` (Product Catalog, Customer Orders có dung lượng ~5.5GB) được xuất định kỳ
       (Synapse Link / Scheduled Export) thành định dạng Parquet.
   - Bước 2 (Lưu trữ Data Lakehouse): Cả 2 luồng dữ liệu đổ trực tiếp vào `Azure Data Lake Storage Gen2 (ADLS Gen2)` dưới dạng
     hồ dữ liệu phân vùng (Partitioned Parquet by Year/Month/Day - Dung lượng tập dữ liệu ~5.5GB, vượt ngưỡng 4GB).
   - Bước 3 (Mô hình hóa dữ liệu Serverless): `Azure Synapse Analytics (Serverless SQL Pool)` sử dụng cú pháp `OPENROWSET(BULK ...)`
     tạo các External Tables / SQL Views trên hồ dữ liệu Parquet, tối ưu hóa truy vấn bằng Partition Pruning và nén Snappy.
   - Bước 4 (Trực quan hóa tức thời): `Power BI Service (SaaS)` kết nối tới Synapse Analytics thông qua chế độ `DirectQuery`.

     + Từ đáy của `Azure Cosmos DB`, kéo đường dây thứ hai chạy song song bên cạnh, cắm thẳng mũi tên `▼` vào nóc của hộp `Azure Data Lake Storage Gen2`. Gắn nhãn: `(Cosmos DB Scheduled Export)`.
     + Từ cạnh trái của `Azure Cosmos DB`, kéo mũi tên đi sang trái cắm vào nóc/cạnh của `Azure Functions (Python Trigger)`. Gắn nhãn: `(Change Feed Streaming)`.
